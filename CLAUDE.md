## What this is

Customer storefront for GlobeGuard GmbH (Cham, Switzerland): OBD diagnostic devices in the tiers BASIC / WoMo / PRO / ELITE, per-brand-group licences, SGW (Security Gateway) licences and bypass cables, Truma adapter cable, remote-diagnosis licences, updates, adapter cables. Talks to the Vendure backend in `../globeguard-backend` over the Shop API only.

## Stack

Next.js 16 App Router, React 19, TypeScript strict, Tailwind 4 (CSS-first tokens in `src/app/[locale]/globals.css`), shadcn "base-vega" on `@base-ui/react` (components take a `render` prop, not Radix `asChild`), next-intl 4, gql.tada (`src/graphql-env.d.ts` generated from the running backend), Vitest (unit), Playwright (e2e). Light theme only. Font Inter via `next/font`.

## Non-negotiable rules

- German is primary (root URLs), English under `/en/` (`localePrefix: 'as-needed'`, `de-CH` formatting). Swiss orthography: `ss`, never `ß`.
- Every user-facing string goes through next-intl. Base catalogues `messages/de.json` + `messages/en.json`; features add their own `messages/<locale>/<feature>.json` (one top-level namespace per file, identical key sets in both locales). The loader in `src/i18n/request.ts` deep-merges them at request time.
- Prices are NET CHF minor units. Display through `<Price value currencyCode="CHF" />` (`src/components/commerce/price.tsx`) with `<VatNote/>` or the full sentence `Configurator.product.vatNote`. EUR is a display-only conversion (x1.1) via the `DisplayCurrencyProvider` cookie; Vendure never receives a currencyCode. Orders are CHF.
- Accounts are mandatory at checkout (backend disables guest checkout): `/checkout` and `/account/*` redirect to `/sign-in?redirectTo=…`.
- No business claims beyond the owner-approved copy ported from the old storefront (see DECISIONS.md and `docs/merge-inventory/`). Placeholders are neutral ("Inhalt folgt").
- Brand name is always "GlobeGuard".
- Commits as `CarloUser <carlobronold@gmail.com>`, no AI attribution trailers.

## Domain logic (frozen)

`src/lib/globeguard/` is the authoritative business logic ported 1:1 from the old storefront and covered by Vitest (`npm test`):

- `picker.ts` – tiers, vehicle types, brand groups, model years, SGW requirements, Erweiterung SKUs, ELITE routing, `?extraBrands` encoding, selection badge.
- `add-on-plan.ts` – `buildAddOnPlan()` (SGW licence/cable lines, PRO extra brands, Truma cable, ELITE Mixed 4..10, ELITE free SGW), `getRequiredAddOnSkus()`, `buildCartLines()`; rule-code warnings (`BLOCKING_WARNINGS` block add-to-cart, `CONFIRM_WARNINGS` need a dialog). Add-on quantities scale with device quantity (decision O9).
- `catalog-adapter.ts` – maps the gql.tada `CatalogProduct` fragment (note the name clash with the domain type; alias on import) to the domain `CatalogProduct`.
- `src/data/brand-compatibility.json` is GENERATED by `../globeguard-backend/scripts/build-catalog-and-compatibility.js` (which copies it here). Never hand-edit.

Change the rules only through the domain module and its tests; UI components only render plans.

## Commands

```bash
npm run dev                  # port 3001, expects the backend on http://localhost:3000/shop-api
npx tsc --noEmit && npx eslint . && npm test     # gates
npm run build                # next build (standalone output); build does not need the backend
npm run test:e2e             # Playwright against E2E_BASE_URL (default http://localhost:3200)
node node_modules/gql.tada/bin/cli.js generate-output   # regenerate src/graphql-env.d.ts from the running backend
                             # (the .cmd shim prints nothing under Git Bash)
npx next typegen             # refresh route types after adding/moving routes
```

Standalone run (what Docker and the Hetzner supervisor do): after `next build`, copy `.next/static` to `.next/standalone/.next/static` and `public` to `.next/standalone/public`, then `PORT=3100 HOSTNAME=0.0.0.0 VENDURE_SHOP_API_URL=… NEXT_PUBLIC_SITE_URL=… node .next/standalone/server.js`. Do not set `HOSTNAME=127.0.0.1` (redirect loop with next-intl). `NEXT_PUBLIC_SITE_URL` and `NEXT_PUBLIC_ASSET_HOST` are build-time values for the client bundle; `VENDURE_SHOP_API_URL` is read at request time. For a local standalone run add `ALLOW_LOCAL_IMAGE_HOSTS=true` at build time (next/image refuses a private-IP upstream in a production build, so product images would 400) and copy the sharp DLLs the tracer misses on Windows — `cp node_modules/@img/sharp-win32-x64/lib/*.dll .next/standalone/node_modules/@img/sharp-win32-x64/lib/` then `rm -rf .next/standalone/.next/cache/images`. Without them sharp cannot load and **next/image silently serves the originals** (634 KB hero instead of 17 KB); see `docs/DEPLOY.md` § Images.

## Payments

Single Mollie tile "Online bezahlen" (method code `mollie`, provisioned by the backend from `MOLLIE_API_KEY`) plus invoice for approved company customers. The review step calls `createMolliePaymentIntent` and redirects externally; `/order-confirmation/[code]` polls the order state (the 3.5.5 plugin has no status-sync mutation). Without a Mollie key the payment step explains that no method is available.
